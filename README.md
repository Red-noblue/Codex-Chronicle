# Codex Chronicle

本地优先的 Codex 对话档案库。把分散在 `.codex` 中的历史记录整理成可阅读、可搜索、可判断去留的会话，再由用户决定归档、移入回收站或删除。

**当前为预览版。** 首次启动默认只读。真实会话写入仅适配 macOS 上已审阅的 Codex 版本和数据库结构；Windows、Linux 的读取与安装包不代表真实删除已获验证。本项目与 OpenAI 无隶属关系。

[下载预览版](https://github.com/Red-noblue/Codex-Chronicle/releases) · [反馈问题](https://github.com/Red-noblue/Codex-Chronicle/issues)

## 可以做什么

- **会话库**：中文界面、项目和时间筛选、全文搜索、消息定位、长对话分段加载、用户与助手阅读视图、独立技术证据视图。
- **会话关系**：识别主对话和子代理，展示关联资产、活动状态和操作影响。
- **批量处理**：刷新后保留选择，影响预览、一次性数字确认、执行进度和失败即停。超过十项增加一次确认，并按每批最多十项处理。
- **归档中心**：本地和 GitHub 私有仓库归档、压缩分片、可选客户端加密、恢复到 `.codex`、本地与云端副本转换、较新版本恢复冲突选择。真实源的恢复仍受相同平台和兼容性门禁约束。
- **存储维护**：临时目录与文件占用扫描、目录级选择、清理预览、执行与恢复材料检查。可执行范围由工作区和服务端权限决定。
- **设置和统计**：亮暗主题、阅读密度、工作区自动发现、账户连接、网络代理、token 与存储统计。

摘要可在本地提取，也可配置云端模型；云端模型会收到所选摘要材料。GitHub 归档需用户主动连接账户并选择仓库；未配置时不会上传会话。

## 下载安装

在 Releases 中选择与设备对应的架构：`arm64` 包括 Apple 芯片和 64 位 ARM 设备，`amd64` 对应 Intel / AMD 64 位设备。

| 系统 | 安装包 | 使用方式 |
| --- | --- | --- |
| macOS 14+ | DMG、ZIP；arm64 / amd64 | 打开 DMG，运行其中的“安装或更新.command”，默认安装到当前用户的“应用程序”文件夹 |
| Windows | 每用户 Setup EXE、便携 ZIP；amd64 / arm64 | 运行安装器，或解压后启动 `bin/codex-chronicle-desktop.exe` |
| Linux | DEB、RPM、tar.gz、ZIP；amd64 / arm64 | 安装对应发行版包，或解压后运行 `bin/codex-chronicle-desktop` |

应用使用系统浏览器显示界面，网页、API、健康检查和启动器控制共用一个本机端口，首选 `127.0.0.1:8787`。默认复用上次成功的地址；端口被其他程序占用时自动选择空闲端口，完成身份与健康检查后打开实际地址。重复启动会复用已核验的实例。首次启动自动检查 `CODEX_HOME` 和 `~/.codex`，也可在“设置 → 工作区”添加目录。

macOS 安装器在提交安装后结束临时检查后台，再交由系统打开正式应用。看到“应用已交由系统启动”后即可关闭安装终端；应用继续通过菜单栏运行。安装器不会退出 Terminal 应用或更改其全局设置。

macOS 菜单栏与 Windows 通知区域（系统托盘）使用原生图标：左键打开工作台，右键展开菜单，macOS 也支持 Control + 单击。菜单展示当前实际地址，可复制地址、设置登录时启动、选择首选端口、开关自动回退、打开日志或安全退出。关闭浏览器不会退出后台；重复打开应用不会增加后台或图标。Windows 图标可能位于通知区域的折叠菜单中。

登录自启动默认关闭，开启后仅显示图标，不主动打开网页。端口设置保存在用户数据目录的 `startup.json`，下次启动生效；主动保存端口后，每次优先尝试该端口，是否避让取决于自动回退开关。显式传入 `--address 127.0.0.1:端口` 优先于保存的设置，并且始终严格使用该地址，冲突会报错。启动失败时仍可从错误窗口打开端口设置，或直接运行启动器 `--startup-settings`；`--status` 可查看已核验实例的实际地址。

Linux 通过会话 D-Bus 的 StatusNotifierItem / DBusMenu 提供托盘，适配支持该协议的 KDE Plasma 等桌面，X11 和 Wayland 共用这套实现。GNOME Shell 通常需要 AppIndicator / KStatusNotifierItem 扩展；点击方式由桌面宿主决定，部分宿主会将左键也用于展开菜单，此时选择“打开工作台”。没有托盘宿主时显示独立“后台管理”窗口；关闭窗口后后台继续运行，再次打开应用可重新进入管理窗口。应用菜单另有“端口设置”和“安全退出后台”快捷动作。无图形桌面时使用 `--no-browser`、`--status`、`--quit`，不会创建图标。

Linux 原生设置和管理窗口使用 `zenity`，打开网页使用 `xdg-utils`，DEB/RPM 会声明这两项依赖；便携包需自行安装。复制地址优先使用 Wayland 的 `wl-copy` 或 X11 的 `xclip`，未安装时显示可选中复制的地址窗口。登录自启动写入 `$XDG_CONFIG_HOME/autostart/codex-chronicle.desktop`，默认是 `~/.config/autostart/`，仅作用于当前用户。托盘、管理窗口和登录启动均不增加 TCP 监听端口。

macOS 包当前只有临时签名，尚无 Developer ID 签名和 Apple 公证，系统可能阻止首次打开；请核对下载来源及 SHA256SUMS 后，在系统“隐私与安全性”中批准。Windows 安装器尚无代码签名。各平台的实际验证范围见对应 Release 说明。

### 数据存放和卸载

程序与用户数据分开保存：

- macOS：`~/Library/Application Support/Codex Chronicle/`
- Windows：`%LOCALAPPDATA%\Codex Chronicle\`
- Linux：`$XDG_DATA_HOME/codex-chronicle/`，未配置时为 `~/.local/share/codex-chronicle/`
- 本地归档默认：用户“文稿 / Documents”下的 `Codex Chronicle/archives/`；可另行选择。

主题、界面密度和已保存筛选会保存在应用数据目录，换端口后仍可恢复；首次使用会导入当前浏览器已有的对应设置。临时选择、会话令牌和阅读位置仍遵循原有浏览器会话与来源范围。

先通过菜单栏或启动器 `--quit` 安全退出后台，再卸载应用或移走便携包。卸载保留配置、索引、归档和恢复材料，也不删除 `.codex`。这些数据可在确认不再需要后由用户另行处理。

### 真实数据操作

默认可以读取正在使用的 `.codex`，**禁止修改正在使用或已加载的目标对话**。同一设备仍有其他 Codex 会话运行时，闲置目标能否执行，取决于锁协议、版本、完整资产关联与数据库事务检查。

当前真实写入仅支持 macOS 当前用户精确的 `~/.codex` 根；需要 Python 3、配套的原生废纸篓桥接程序及正在运行的 Codex daemon socket。已审阅的 daemon 版本为 `0.166.0`、`0.167.0`、`0.167.2`、`0.169.0`，数据库 schema 也必须匹配。

安装版高级用户可在用户数据目录创建 `launcher.json` 后重启：

```json
{
  "scan_root": "/absolute/home/.codex",
  "real_conversation_write": true,
  "python": "/absolute/path/to/python3",
  "daemon_socket": "/absolute/path/to/codex-daemon.sock"
}
```

不要照抄示例路径；请使用本机真实的绝对路径。开启开关只允许进入执行流程：每次仍须扫描、检查活动和锁、解析专属资产、预览、准备恢复材料、dry-run、数字确认。未知 schema、关联不完整、共享资产归属不明、文件变化或数据库 busy 都会阻断。

“移入回收站”会将正文及必要恢复材料作为会话包移走；“删除”移除源会话，成功后清理本次临时恢复正文。共享 SQLite 按目标记录处理，不会整库移动或删除；事务由 SQLite 正常维护 WAL/SHM。归档副本的删除是独立操作。

## 从源码运行

依赖 Go（版本见 `go.mod`）、Node.js 22+、Python 3（集成测试）；macOS 桌面菜单栏构建还需要 Xcode Command Line Tools。

```bash
cd web
npm ci
npm run check
npm run build
cd ..
go test ./...
go vet ./...
python3 -m unittest discover -s docs/项目验证 -p test_authorized_live.py
go run ./cmd/codex-chronicle --scan-root /absolute/path/to/codex-home --archive-db /absolute/path/to/chronicle-data/archive.db --web-root web/dist
```

默认只监听本机。需要远程访问时，必须显式启用 `--allow-remote`，通过一次性绑定码建立会话，并自行配置 TLS 反向代理。

源码运行时也使用 `http://127.0.0.1:8787/`，前端修改后重新执行 `npm run build`。`npm run dev` 使用的 `5173` 仅供需要热更新的前端开发调试，不作为发布入口；发布包不启动 Vite。

构建安装包：

```bash
bash scripts/build-release.sh 0.1.0-preview.11 darwin arm64
```

支持 `darwin / windows / linux` 与 `arm64 / amd64` 组合；macOS 包须在 macOS 构建。Windows EXE、Linux DEB/RPM 由仓库 Actions 工作流进一步封装。

## 工程结构

Go 后端是一个本地进程，前端使用 Svelte 5 + TypeScript，无微服务。兼容层隔离 Codex 文件、SQLite schema 与活动锁协议，便于后续适配新版本。

- `cmd/`：后台、桌面启动器、原生回收站桥接、发布打包命令。
- `internal/compat/`：JSONL / SQLite 兼容及受限真实执行器。
- `internal/catalog/`、`application/`、`store/`：流式读取、检索和独立控制面数据库。
- `internal/api/`：本地 HTTP API；`operation/`、`maintenance/`：生命周期与维护。
- `internal/archive/`：归档及远端存储；`desktop/`、`update/`：安装与更新。
- `web/`：中文工作台；`packaging/`、`scripts/`：安装和验证。
- `docs/项目验证/`：公开的合成测试生成器及兼容入口，不包含真实对话正文。

## 验证与已知限制

GitHub Releases 保存公开安装包、版本说明、摘要和冻结候选清单；Actions 的临时候选不等同于公开版本。“验证与发布”工作流分为 `candidate`（三系统回归、六平台打包、验证最终 ZIP、冻结并生成构建来源证明）、`verify`（选择已成功的构建编号与清单 SHA-256，重新核验原字节和来源）和 `publish`（仅 main 可执行，将同一候选上传至不可变 Release）。正式版候选还必须指定仓库内已审核的发布说明。发布阶段不重新编译，也不覆盖同名资产；同名草稿只能补传缺失文件，摘要不一致则停止。

公开发布必须来自 main 的成功候选，核对三系统、六平台和候选冻结门禁，并验证 GitHub OIDC 构建身份、源码提交、分支和受信任工作流。发布成功后才推进静态更新索引；公开版本的资产与标签保持不可变，暂停、撤回只调整分发策略。发布环境和主线权限由仓库维护者控制，系统签名与公证的实际限制仍以下述说明为准。

公开发布从本机执行 `python3 scripts/release-candidate.py dispatch-publish --version 目标版本 --repository Red-noblue/Codex-Chronicle --run-id 成功候选编号 --expected-sha256 冻结清单摘要`。操作者通过本机 GitHub 登录核验需要管理权限的仓库不可变设置，并固定候选源码标签，再派发 main 上的发布工作流；CI 使用最小权限令牌，不保存个人管理令牌。工作流要求本次不可变设置确认，并在公开后严格核验 `immutable`；未确认、同名标签冲突、资产不符或未锁定时不推进更新索引。

macOS 本机验证包括安装、覆盖更新、回退、安装中断恢复、隔离更新源下载、签名校验、坏候选拒绝、强杀后恢复，以及选定真实会话的生命周期实验。合成 fixture、稳定副本、隔离实时实验和真实源实验分别作为不同证据；不把它们当成全部设备均安全的保证。

安装版默认自动更新，可在“设置 → 系统与更新”关闭、手动检查或配置下载代理。启动后后台检查，此后每 6 小时检查一次，下载、验签和预检完成后等待网页不可见且没有后台任务的 5 分钟空闲窗口，再安全重启；自动重启不主动打开浏览器。仍可手动“立即更新并重启”或选择“稍后重启”。网络失败会退避重试，已回退或校验失败的版本不会被自动反复安装。

下载中断后保留同一包身份的片段，支持 HTTP Range / If-Range 续传；服务器忽略范围时从头下载，错误范围或校验不一致的片段会丢弃，完整摘要与签名通过前不可安装。页面显示已下载字节和续传状态；片段超过 7 天后在恢复维护时清理。下载、展开、程序复制与项目快照前检查当前用户的可用磁盘空间，空间不足不切换版本。

正式和预览通道分别使用 `update-feeds/stable.json`、`update-feeds/preview.json` 静态索引。发布方可通过 GitHub Actions“维护更新策略”暂停、恢复通道或撤回指定版本，原因会提供给新客户端；新发布保留人工暂停和撤回记录，不覆盖公开安装包。在线候选在提交前及实际重启前复核原渠道与包身份，暂时断网或暂停时等待重试，撤回版本不再自动安装。暂停或撤回当前候选会隐藏公开下载项，阻止旧客户端继续下载；旧版已经准备好的计划无法追溯补上新版的安装前复核，首次升级仍需留意发布说明。

重启先等待任务与旧托盘正常退出，再保存项目数据库和启动设置快照，暂停启动候选版本；实际健康检查通过并持久化提交决定后才开放操作。提交前启动失败或中断会恢复旧版本与启动前快照，提交后不再用旧快照覆盖用户新增数据。首次健康确认后保留 24 小时恢复窗口，时间持久化，重启不会重新计时；到期自动清理本应用下载的安装包、解压预检副本、旧版本及冗余基线副本，文件被占用时稍后重试。当前程序、系统启动入口和待处理更新继续保留，不清理用户手动选择的外部离线包。关闭自动更新不影响到期清理，恢复窗口结束后不再提供旧版本一键回退。

上述策略随包含该实现的新安装包提供，`preview.14` 的旧界面首次升级时仍需手动退出后台再打开；手动运行的开发服务由部署者自行重启。24 小时窗口、6 小时检查和 5 分钟空闲是本项目的默认值，并非所参考产品公开承诺的统一时限。异常重启不会自动继续删除会话任务，需要人工复核；会话保留规则仍未开放无人值守自动删除。

更新失败时，可在“设置 → 系统与更新”选择“导出更新诊断”。诊断包只在本地生成，包含系统与架构、更新状态、最近 192 条阶段事件和故障编号；不收集原始日志、对话、数据库、恢复快照或认证文件，网址、凭据和私人路径会过滤。事件记录独立于安装包的 24 小时清理，达到上限后滚动保留。后台无法启动时，可运行安装包内的启动器 `--export-diagnostics 新文件.zip` 离线导出；可同时传入 `--data-dir` 指定本应用数据目录。离线导出不会启动后台，不覆盖已有文件，损坏或无法读取的来源会在报告中注明。

反馈问题时请提供系统、版本、复现步骤、故障编号及检查后的诊断包；不要提交会话正文、认证文件、令牌、数据库或恢复包。诊断导出不自动上传。
